system_setup / Step 2

Step 2 · Ubuntu

Essential commands

A fresh Ubuntu install is deliberately minimal. This step adds the tools you will reach for daily — and the ones every later step quietly depends on.

Run this

$ curl -fsSL https://aikaryashala.com/system_setup/scripts/install_cmds.sh | bash

It will ask for your Linux password once, at the start — installing software system-wide needs administrator rights. Re-running it later is safe; anything already installed is skipped.

What gets installed

Fetching and networking

  • curlFetch a URL. The workhorse behind every install command on this site.
  • wgetAlso fetches URLs; better at large or resumable downloads.
  • sshLog in to another machine securely. ssh-keygen creates your keys.
  • rsyncCopy directories efficiently — only what changed, locally or over ssh.
  • pingIs that host reachable at all?
  • digAsk DNS what a name resolves to.
  • ipip addr shows your addresses, ip route shows where traffic goes.
  • ncNetcat: open a raw TCP connection. Invaluable for testing a port.

Version control

  • gitTrack changes, and clone anything from GitHub.
  • gnupgVerify signatures — used when adding third-party package repositories.

Editing and reading

  • nanoA simple editor. Arrow keys work, Ctrl+O saves, Ctrl+X exits.
  • vimThe powerful one. :q! gets you out.
  • lessPage through long output. Space scrolls, / searches, q quits.
  • batLike cat, but with syntax highlighting and line numbers.
  • fileTell me what this file actually is, regardless of its extension.
  • dos2unixStrip Windows line endings — a common annoyance when files come from the C: drive.

Searching

  • rgripgrep: search file contents across a whole project, fast, skipping ignored files.
  • fdFind files by name, with sane defaults.
  • fzfFuzzy-pick from any list. Press Ctrl+R to search your command history.
  • jqRead, filter and reshape JSON.

Working in the terminal

  • tmuxSplit the terminal, and keep sessions alive when you disconnect.
  • treeShow a directory as a tree.
  • htopWhat is using my CPU and memory, right now.
  • ncduWhat is using my disk. Navigable, unlike du.
  • zip unzip tarArchives, in every format you will meet.
Why bat and fd need a fix-up

Ubuntu ships these as batcat and fdfind, because the names bat and fd were already taken by other packages. The script creates links in ~/.local/bin so the normal names work, and makes sure that directory is on your PATH.

Try them

# search every file under the current directory for a word
$ rg "TODO"

# find files by name, anywhere below here
$ fd "\.c$"

# look at a file with syntax highlighting
$ bat hello.c

# pull one field out of a JSON response
$ curl -s https://api.github.com/repos/aikaryashala/system_setup | jq -r .full_name

# what is this file, really?
$ file /bin/ls
/bin/ls: ELF 64-bit LSB pie executable, x86-64, dynamically linked

Set up git

The script installs git but deliberately does not configure your identity — that part is yours. Run these once, with your own name and email: 

$ git config --global user.name "Your Name"
$ git config --global user.email "you@example.com"
$ git config --global init.defaultBranch main
$ git config --global core.editor nano

To connect to GitHub over SSH, create a key and add the public half to your account:

$ ssh-keygen -t ed25519 -C "you@example.com"
$ cat ~/.ssh/id_ed25519.pub

Copy that output into GitHub → Settings → SSH keys, then check it works with ssh -T git@github.com.

Check it worked

The script prints a version summary when it finishes. To confirm by hand, open a fresh terminal — or reload your shell settings — and run: 

$ source ~/.bashrc
$ git --version && rg --version && jq --version && bat --version
“command not found” right after installing

Your shell caches where commands live, and the script adds ~/.local/bin to your PATH. Run source ~/.bashrc, or just close and reopen the terminal.
